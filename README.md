# Два VPS для связки «вход + выход»: инструкция с нуля

## 0. Что строим и зачем два сервера

```
твой телефон/ПК ──▶ VPS-A (вход, доступен из РФ) ──туннель──▶ VPS-B (выход, скрыт) ──▶ интернет
```

- **VPS-A (вход)** — единственная точка, которую видят твои устройства и провайдер. Его адрес обязан быть доступен из России.
- **VPS-B (выход)** — его адрес видят сайты и сервисы. Он может быть заблокирован в РФ, и это нормально: устройства к нему напрямую не обращаются.

Схема из двух серверов нужна, когда один адрес нельзя светить или он уже в блокировках, а вход должен оставаться стабильным.

## 1. Какой VPS брать

### Общие требования к обоим

| Параметр | Что нужно | Почему |
|---|---|---|
| Виртуализация | **KVM** (или VMware), НЕ OpenVZ/LXC | Внутри ставится DKMS-модуль ядра (AmneziaWG). В контейнерах модули ядра поставить нельзя |
| ОС | **Ubuntu 24.04 LTS** (или 22.04) | Под неё все пакеты и инструкции |
| IPv4 | **Выделенный** | По одному IPv6 схема не собирается |
| CPU / RAM / диск | 1 vCPU / 1 ГБ RAM / 10–20 ГБ SSD | Хватает с запасом, больше не нужно |
| Трафик | от 1 ТБ/мес или безлимит | Иначе упрёшься в лимит за неделю |
| Оплата | помесячно | Проще сменить сервер, если попадётся плохой адрес |

### Отдельно про VPS-A (вход)

- **Главный критерий — адрес реально открывается из России.** Российский сервер этому удовлетворяет по определению; зарубежный надо проверять: у дешёвых хостингов бывают «грязные» диапазоны, уже попавшие в блок-листы.
- **Локация: Россия подходит** и даёт минимальный пинг и стабильный маршрут. Но есть риск юрисдикции: хостер по требованию РКН обязан блокировать, а за VPN/прокси может расторгнуть договор.
- Отдельно помни, что **A — единственная публичная точка**: все твои устройства привязаны к его адресу. Заблокируют A — встанет всё, и менять придётся вместе со всеми клиентами. B меняется легко, A — болезненно.
- Зарубежный A (Германия, Нидерланды, Финляндия) выбирают, когда важнее устойчивость входа, чем пинг: адрес вне юрисдикции РКН сложнее убрать административно.
- Провайдер не должен резать нестандартные порты — проверить после покупки: `Test-NetConnection <IP> -Port 8443`.

### Отдельно про VPS-B (выход)

- Локация — другая страна и **другой провайдер**, чем у A.
- Главное — **чистота IP**: его будут видеть сайты, банки, сервисы. Если хостинг даёт тестовый период или показывает диапазон адресов — пользуйся этим.
- Недоступность B из РФ не является недостатком. Это одна из причин, по которым схема делается из двух серверов.

### Примеры хостингов

Критерии важнее бренда: KVM, Ubuntu, выделенный IPv4, приемлемая оплата. Обычно называют Timeweb Cloud, Aeza, VDSina, Hostkey, PQ Hosting, 4vps, а также европейские KVM-хостинги. Смотри не на цену, а на отзывы про блокировки диапазонов.

## 2. Что придёт после заказа

В письме или панели:

- **IP-адрес** (например `203.0.113.10`)
- **пользователь** — обычно `root`
- **пароль** root (или сразу приватный ключ)
- **порт SSH** — обычно 22, иногда 2222 или другой

Сохрани это в надёжном месте.

## 3. Подключение по SSH

### 3.1. Штатный ssh в Windows (ничего ставить не надо)

Проверка, что клиент есть (Windows 10 1809+ и Windows 11 — есть всегда):

```powershell
ssh -V
```

Подключение:

```powershell
ssh root@203.0.113.10
```

- первый раз спросит про отпечаток ключа — ответь `yes` и Enter;
- пароль вводится **вслепую**: символы не отображаются, это нормально. Ввёл и нажал Enter;
- другой порт: `ssh -p 2222 root@203.0.113.10`.

**Вход по ключу, без пароля.** Генерируем пару:

```powershell
ssh-keygen -t ed25519 -C "my-vps"
```

Три раза Enter (путь по умолчанию, парольную фразу можно не задавать).

Копируем публичный ключ на сервер:

```powershell
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh root@203.0.113.10 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

Проверка: `ssh root@203.0.113.10` должен пустить без пароля.

**Алиасы вместо адресов.** Файл `C:\Users\<ты>\.ssh\config` (создать, если нет):

```
Host a
    HostName 203.0.113.10
    User root

Host b
    HostName 198.51.100.20
    User root
    ProxyJump a
```

Дальше просто `ssh a` и `ssh b`. Второй заходит **через первый** — выручает, когда B напрямую недоступен.

**Копирование файлов:**

```powershell
scp C:\Temp\file.txt a:/root/
scp a:/root/diag-a.txt C:\Temp\
```

**Диагностика, если что-то не так:** `ssh -v root@IP` — покажет, на каком этапе спотыкается.

### 3.2. MobaXterm Portable (удобнее для новичка)

1. Скачай **Portable edition** (zip) с `mobaxterm.mobatek.net`, распакуй в любую папку, запусти `MobaXterm_Personal_XX.X.exe`. Установка не требуется, можно носить на флешке.
2. `Session` → `New session` → выбери **SSH**.
3. Заполни: `Remote host` = IP, `Specify username` = `root`, `Port` = 22 → OK.
4. Введи пароль. Галочка «Save password» избавит от ввода при следующих запусках.
5. Что получаешь: терминал + **слева панель SFTP** — файлы перетаскиваются мышкой в обе стороны. Есть встроенный редактор и сохранение сессий.
6. Полезное: кнопка `Start local terminal` — локальная консоль Windows в том же окне; `MultiExec` — отправить одну команду сразу в несколько сессий (удобно, когда правишь оба сервера одинаково).
7. Вход по ключу: `Session` → `Advanced SSH settings` → `Use private key` → указать `id_ed25519`.

### 3.3. Если SSH не подключается

| Симптом | Что проверить |
|---|---|
| `Connection timed out` | Порт или адрес закрыт: `Test-NetConnection <IP> -Port 22`. Часто это блокировка у провайдера |
| `Connection refused` | Сервер доступен, но sshd не слушает: другой порт либо сервис лежит |
| `Permission denied` | Не тот пользователь, пароль или ключ |
| Работало, потом перестало | Сменился IP сервера или включилась блокировка. Проверь из другой сети (мобильный интернет) |
| B недоступен из РФ, A доступен | Ходи на B через прыжок: `Host b` + `ProxyJump a` |

## 4. Первичная настройка (на обоих серверах)

```bash
apt update && apt upgrade -y
apt install -y ufw curl nano htop
```

**Закрываем фаервол, оставляя SSH:**

```bash
ufw allow 22/tcp
ufw --force enable
ufw status
```

**И сразу то, что сэкономит день позже** — заголовки ядра и сборочные пакеты. Без них DKMS-модуль AmneziaWG не соберётся под новое ядро, и после обновления системы туннель перестанет подниматься:

```bash
apt install -y linux-headers-generic build-essential bc libelf-dev dwarves
```

Проверка:

```bash
uname -r
dpkg -l | grep linux-headers-generic
```

## 5. Порядок дальнейшей сборки

1. **AmneziaWG на обоих** — установка пакета и DKMS, проверка, что модуль собирается под текущее ядро.
2. **Туннель A ↔ B** — awg0 на B (сервер) и на A (клиент), проверка `awg show` и handshake.
3. **MTProto** — telemt на B плюс TCP-релей haproxy на A.
4. **VPN для устройств** — интерфейс awg1 на A; устройства добавляются скриптом `amnezia-add.sh`.
5. **Маршрутизация и NAT** — чтобы устройства выходили в интернет через B. Применяется скриптом `up-all-a.sh` (на A) и `up-all-b.sh` (на B).
6. **SOCKS5** — сервер на B, релей на A, доступ только для своих адресов. Открытие портов входит в `up-all-a.sh` и `up-all-b.sh`.
7. **Проверка** — прогон `up-all-a.sh` и `up-all-b.sh`: они поднимут всё недостающее и сами отчитаются, где проблема.
8. **Тест перезагрузкой** — единственная честная проверка, что схема живучая.

## 6. Три вспомогательных скрипта

Все три лежат в `/usr/local/sbin/` на своих серверах. Настройки (адреса, порты, имена сервисов) вынесены в начало каждого файла — править нужно только их.

| Скрипт | Где | Что делает |
|---|---|---|
| `up-all-a.sh` | на A | Поднимает весь входной стек: модуль amneziawg, awg0/awg1, маршрутизацию VPN в B, docker и haproxy (MTProto + SOCKS5), открывает 22, 443/tcp, 8443/udp, 8440/tcp для своих IP, проверяет все три порта |
| `up-all-b.sh` | на B | Поднимает выходной стек: модуль, awg0, telemt, SOCKS5, форвард и NAT, открывает 22, 8443/udp от A, 443/tcp и 1080/tcp от адреса A в туннеле, проверяет порты и handshake |
| `amnezia-add.sh` | на A | Добавляет устройство в AmneziaWG: подбирает свободный адрес, создаёт ключи, добавляет пира в конфиг и на живой интерфейс, генерирует клиентский конфиг и QR |

### 6.1. `up-all-a.sh` — подъём всего на входе

```bash
bash /usr/local/sbin/up-all-a.sh
```

Безопасен для повторного запуска: интерфейсы поднимаются только если их нет, сервисы — только если не запущены, правила ufw добавляются идемпотентно. В конце печатает отчёт по каждому пункту.

Что проверяет на выходе: слушается ли 443/tcp (MTProto), 8443/udp (Amnezia) и 8440/tcp (SOCKS5), отвечает ли MTProto-цепочка через B, есть ли handshake с устройством и с B.

### 6.2. `up-all-b.sh` — подъём всего на выходе

```bash
bash /usr/local/sbin/up-all-b.sh
```

То же самое для B: восстанавливает `ip_forward`, MASQUERADE и `ufw route` для форварда VPN-трафика, стартует telemt и SOCKS5, проверяет, что оба слушают туннельный адрес, и что NAT-правило на месте.

Ровно этот скрипт спасает после перезагрузки B, когда MASQUERADE теряется и устройства остаются без интернета.

### 6.3. `amnezia-add.sh` — новое устройство

```bash
amnezia-add.sh dima_phone          # адрес подберётся автоматически
amnezia-add.sh dima_pc 18          # задать адрес вручную (18 -> 10.20.20.18)
amnezia-add.sh --list              # кто уже добавлен
amnezia-add.sh --delete dima_pc    # удалить устройство
```

Особенности: параметры обфускации и публичный ключ сервера берутся **из реального конфига** awg1, поэтому клиентский конфиг всегда совпадает с сервером. Перед правкой `awg1.conf` делается бэкап, после — проверяется, что пир реально появился на интерфейсе. Устройство начинает работать сразу, без перезапуска туннеля.

## 7. Грабли, на которые наступают все

- **OpenVZ/LXC вместо KVM** — модули ядра не поставить, схема не соберётся вовсе.
- **Обновление ядра без пересборки модуля** — после ребута нет интерфейсов. Не удаляй интерфейсы, пока `dkms status` не покажет `installed` для работающего ядра.
- **Забытое правило UDP** — Amnezia «не подключается», хотя TCP-порт открыт: туннель ходит по UDP.
- **Открытый SOCKS5** — прокси нельзя оставлять доступным всему интернету, только своим адресам.
- **Динамический IP клиента** — правило фаервола отваливается при смене адреса; нужен автоапдейт или разрешение подсети.
- **Смена IP сервера** — не забудь обновить endpoint на втором сервере.

## 8. Быстрая шпаргалка после перезагрузки

Если что-то отвалилось — сначала прогони скрипты, они восстанавливают большую часть сами:

```bash
# на A
bash /usr/local/sbin/up-all-a.sh

# на B
bash /usr/local/sbin/up-all-b.sh
```

Затем проверь три сервиса с клиента:

| Что проверяем | Как |
|---|---|
| MTProto | подключиться в Telegram по ссылке `tg://proxy?server=<IP A>&port=443&...` |
| Amnezia | включить VPN на устройстве, `curl ifconfig.me` должен показать адрес **B** |
| SOCKS5 | `curl -x socks5h://user:pass@<IP A>:8440 https://ifconfig.me/ip` — тоже адрес **B** |

Если `ifconfig.me` показывает адрес A вместо B — значит туннель A→B поднят, но не работает выход через B: проверь `up-all-b.sh` и endpoint на A.
